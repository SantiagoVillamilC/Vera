# Vera — Agent Guide

Flutter mobile app (iOS + Android). Dart SDK ^3.12, Material 3.

## Stack

| Layer | Package |
|---|---|
| State management | `flutter_riverpod` 2.x + `riverpod_annotation` (code gen) |
| Navigation | `go_router` 14.x |
| HTTP | `package:http` (add when needed) |
| Code generation | `build_runner` + `riverpod_generator` |

## Commands

```bash
flutter run -d <device-id>                            # run app
flutter devices                                       # list devices
dart run build_runner build --delete-conflicting-outputs  # generate Riverpod code
dart run build_runner watch --delete-conflicting-outputs  # watch mode
flutter analyze                                       # static analysis
flutter test                                          # run tests
flutter test --coverage                               # with LCOV coverage
```

**Always run `build_runner build` after adding or modifying `@riverpod` annotated classes.**

## Project layout

```
lib/
├── main.dart                    # entry point — ProviderScope wraps App
├── app/
│   ├── app.dart                 # MaterialApp.router, reads AppThemeMode provider
│   └── router.dart              # all GoRouter routes
├── core/
│   └── theme/
│       ├── app_theme.dart       # ThemeData light + dark
│       ├── theme_provider.dart  # AppThemeMode @riverpod notifier
│       └── theme_provider.g.dart
└── features/
    └── <feature>/
        ├── data/                # repositories, data sources, JSON models
        ├── domain/              # entities, use cases (optional for simple features)
        └── presentation/        # screens, widgets, UI providers
```

## Conventions

### Adding a new feature

1. Create `lib/features/<name>/presentation/<name>_screen.dart`
2. Add route in `lib/app/router.dart`
3. Create providers with `@riverpod` annotation, run `build_runner build`

### Riverpod providers

Always use code generation:

```dart
import 'package:riverpod_annotation/riverpod_annotation.dart';
part 'my_provider.g.dart';

@riverpod
class MyNotifier extends _$MyNotifier {
  @override
  MyState build() => MyState.initial();
}
```

Generated provider name: `myNotifierProvider`. Access via `ref.watch(myNotifierProvider)`.

- `ConsumerWidget` for stateless widgets that read providers
- `ConsumerStatefulWidget` when local widget state is also needed
- Never use `setState` — delegate state to Riverpod

### Navigation

```dart
context.go('/path');    // replace current route
context.push('/path');  // push onto stack
```

All routes declared in `lib/app/router.dart`. Use named routes for deep linking.

### Theme

`AppThemeMode` notifier controls `ThemeMode`:
- Toggle: `ref.read(appThemeModeProvider.notifier).toggle()`
- Set: `ref.read(appThemeModeProvider.notifier).setMode(ThemeMode.dark)`

### JSON models

Place models in `features/<name>/data/`. Use `fromJson`/`toJson` manually or with `json_serializable`. See `flutter-implement-json-serialization` skill for the pattern.

## Files to never edit

- `*.g.dart` — generated by build_runner
- `ios/`, `android/` platform folders — modify only via `flutter` CLI or platform-specific config

## Testing

- Unit tests: `test/` mirroring `lib/` structure
- Widget tests: wrap with `ProviderScope` + override providers as needed
- Integration tests: `integration_test/` using `flutter_test` driver

```dart
// Widget test example
await tester.pumpWidget(
  ProviderScope(
    overrides: [myProvider.overrideWith(() => FakeNotifier())],
    child: const App(),
  ),
);
```
